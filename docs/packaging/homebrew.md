# Homebrew

`clickcast` ships a Homebrew formula (`Formula/clickcast.rb`) so macOS/Linux
users who don't want to think about Python venvs can install it the same way
they'd install `gh` or `jq`. This is v1/day-one distribution per [#170] --
see that issue for the full rationale and rollout plan.

## What's live today vs. what needs bootstrapping

| Install path | Status |
| --- | --- |
| `brew install --build-from-source ./Formula/clickcast.rb` (clone this repo) | **Works today** -- no setup required. |
| `brew install AlexKay28/clickcast/clickcast` | **Needs the one-time bootstrap below** -- the `AlexKay28/homebrew-clickcast` tap repo doesn't exist yet. |
| `brew install clickcast` (homebrew-core) | Explicitly out of scope for this PR -- see [#170]'s "Suggested rollout" (v0.4.x+, after release cadence/track record). |

## How it works

`Formula/clickcast.rb` is generated by [`scripts/homebrew_formula.py`](../../scripts/homebrew_formula.py)
from a version + PyPI sdist URL/sha256:

```bash
python scripts/homebrew_formula.py 0.3.0 --out Formula/clickcast.rb
```

Run with no `--url`/`--sha256`, it looks the sdist up on PyPI's JSON API
(`https://pypi.org/pypi/clickcast/<version>/json`) automatically. The
`.github/workflows/homebrew-tap.yml` CI job does exactly this on every
published GitHub release, then pushes the result to
`AlexKay28/homebrew-clickcast`.

### Formula design

- **`include Language::Python::Virtualenv` + a single `pip_install`, not a
  `resource` block per dependency.** The fully idiomatic Homebrew pattern
  pins every transitive dependency (playwright, Pillow, imageio, pydantic,
  ...) as its own `resource "name" do ... end` block with its own sha256, so
  the whole install is hermetic and reproducible offline. Generating and
  maintaining that block set on every release is significant tooling for
  v1 -- issue #170 explicitly allows picking the simpler option "after
  prototyping." `venv.pip_install "clickcast==#{version}"` resolves
  clickcast's dependencies from PyPI at install time instead: less to
  maintain, but not hermetic (a transitive dependency could theoretically
  publish a new version between clickcast releases and change what gets
  installed). Revisit if this bites in practice -- the migration path is
  additive (add `resource` blocks; the `install` method changes little).
- **`depends_on "python@3.12"`** -- a single pinned Python, not a floor. Every
  `clickcast==X.Y.Z` release supports 3.10-3.13 (see `pyproject.toml`), but
  the venv formula needs to pick exactly one to build against.
- **No `depends_on "ffmpeg"`.** clickcast already bundles one via the Python
  `imageio[ffmpeg]` dependency. Issue #170 flags this explicitly: declaring
  a system ffmpeg here would put a second copy on disk for every user, for
  no benefit. If a user's workflow needs a *system* ffmpeg for other tools,
  `brew install ffmpeg` remains independent and unaffected.
- **No Chromium.** It's a ~200MB download versioned independently of
  clickcast itself -- bundling it would bloat the formula and go stale
  between clickcast releases. The formula's `caveats` block instead points
  at the `clickcast install --with-deps chromium` command (already part of
  the CLI) as a required post-install step.
- **`test do`** runs `clickcast --version` and asserts it matches the
  formula's version -- catches an install that silently didn't wire up the
  entry point correctly.

## Verification performed for this PR

`brew` was not available in the sandbox this PR was built in, so
`brew install --build-from-source` / `brew audit` / `brew style` could not be
run directly. What *was* verified:

- The generated formula was checked by hand against Homebrew's own
  ["Python for Formula Authors"](https://docs.brew.sh/Python-for-Formula-Authors)
  cookbook -- the `virtualenv_create` + `pip_install` + `bin.install_symlink`
  pattern, the `caveats`/`test do` block shapes.
- `scripts/homebrew_formula.py` has unit tests
  (`tests/test_homebrew_formula.py`) covering the rendered formula's
  structure (Ruby class shape, pinned Python, no ffmpeg dependency, caveats
  content, version-checking test block) and the PyPI lookup logic (mocked,
  including a 404/no-sdist-published error path).
- `Formula/clickcast.rb` as checked into this repo was generated against the
  **real, already-published** `clickcast==0.2.9` sdist on PyPI (its actual
  sha256 was fetched live), so `brew install --build-from-source
  ./Formula/clickcast.rb` should work as-is once run on a machine with
  Homebrew installed -- this just wasn't possible to confirm in this
  sandbox.

Whoever bootstraps the tap (below) should run a real `brew install
--build-from-source ./Formula/clickcast.rb && clickcast --version` as the
first live check.

## One-time bootstrap (repo owner only)

Nothing below can be done by an agent working in this repo -- it requires
creating a separate GitHub repository and, for the tap-push step, generating
a personal access token. These are exactly the kind of manual, owner-only
steps issue #206/#209 established a precedent for (there: leaving the GitHub
Marketplace listing as a documented manual step rather than an automated
one).

1. **Create the tap repository.** On GitHub, create
   `AlexKay28/homebrew-clickcast` (public, MIT license recommended to match
   this repo). Homebrew requires the `homebrew-<name>` naming convention for
   third-party taps. Add a `Formula/` directory; a first commit with the
   `Formula/clickcast.rb` from this repo is enough to seed it (or leave it
   empty -- the CI workflow below will populate it on the next release).

2. **Create a push token.** Go to
   https://github.com/settings/personal-access-tokens/new (fine-grained PAT)
   and create a token scoped to **only** the `AlexKay28/homebrew-clickcast`
   repository, with **Contents: Read and write** permission. (A classic PAT
   with the `repo` scope also works but is broader than necessary.)

3. **Add the token as a secret on the `clickcast` repo** (not the tap repo):
   Settings -> Secrets and variables -> Actions -> New repository secret,
   name `HOMEBREW_TAP_TOKEN`, value the token from step 2.

4. **Verify the next release picks it up.** Cut a release per
   [`RELEASING.md`](../../RELEASING.md) as usual. Once `release.yml`'s
   `gh-release` job publishes the GitHub release,
   `.github/workflows/homebrew-tap.yml` fires automatically, renders the
   formula for the new version, and pushes it to
   `AlexKay28/homebrew-clickcast`. Check that repo's `Formula/clickcast.rb`
   updated and that the workflow run's log shows a successful push (not the
   "HOMEBREW_TAP_TOKEN is not set" warning).

5. **Smoke-test the real tap install:**

   ```bash
   brew install AlexKay28/clickcast/clickcast
   clickcast --version
   clickcast install --with-deps chromium
   ```

6. **(Optional, later) Apply to `homebrew-core`.** Once there's a release
   track record, follow
   https://docs.brew.sh/Adding-Software-to-Homebrew -- explicitly out of
   scope for this PR per [#170]'s rollout plan.
